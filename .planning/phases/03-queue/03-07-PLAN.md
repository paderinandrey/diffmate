    - Different head while one automatic job is queued with a non-null next_attempt_at, even when retry_count is greater than 0 or a run row exists: same job id, queued_head replaced, retry_count set to 0, next_attempt_at set to now_ms + debounce_ms, still one job
    - Same head while that retry or debounce job is queued: same job id, same next_attempt_at, same retry_count

    - Running review job: no insert, no queued_head write, and no next_attempt_at or retry_count change
    - Draft, untracked, head None, or any run already stored for that head: no new job
    - Absent::Open { is_draft: false, head_sha: Some(new) } on a target that is still tracked after the tracking update uses the same arming rule as a seen ready PR. The same variant on an untracked target inserts no job
    - After a successful run, schedule_after_run reads the targets.head_sha the runner stored with set_known_head. When that head differs from the finished run's head and no run exists for it, one new automatic job is inserted with retry_count 0 and next_attempt_at = now_ms + debounce_ms. The finished run stays succeeded
    - schedule_after_run when a queued automatic job has a non-null next_attempt_at and head_sha differs from queued_head, or from the latest run head when queued_head is null, resets that one job the same way. When the head matches, a waiting retry keeps its next_attempt_at
    - Neither path writes head_sha or head_checked_at
  </behavior>
  <action>
    In the same apply_poll transaction, after the tracking updates, schedule from the post-update rows. A target is eligible when tracking is tracked, it is not a draft, and head_sha is Some. That covers a SeenRequest and an Absent::Open { is_draft: false, head_sha: Some(_) } on a target that stayed tracked. Absent::Open on an untracked target is not eligible. Do not insert a job when any run for that head already exists, succeeded or not: a give-up stays terminal, and a retry stays on the requeued job. Insert with the same column list enqueue_review uses, origin automatic, force 0, next_attempt_at = now_ms + debounce_ms, queued_head = head, and retry_count 0.

    Any queued automatic review job with a non-null next_attempt_at is the one waiting job, whether retry_count is 0 or not and whether a run row exists. A different head updates queued_head, sets retry_count to 0, and sets next_attempt_at to now_ms + debounce_ms. The same head leaves the row alone. A queued job with a null next_attempt_at, including debug enqueue, is left alone and blocks a second job. A running review job is left alone: do not write queued_head and do not reset it. Do not attach through enqueue_review; that helper would not set next_attempt_at and would fold a new head into a retry.

    schedule_after_run is called only after a successful automatic review returns. By then src/runner/run.rs has already written targets.head_sha from the post-agent pr view when that view succeeded. That column is the latest known head. This function reads it, queued_head, and the finished run's head. It no-ops when head_sha is null, when a review job is running, when head_sha equals the finished run's head and no queued automatic job has a different queued_head, or when a run for head_sha already exists. When head_sha differs from the finished run and no queued job exists, it inserts one debounce job for head_sha. When a queued automatic job has a non-null next_attempt_at and the head differs from queued_head, or from the latest run head if queued_head is null, it resets that one job: same job, queued_head replaced, retry_count 0, next_attempt_at = now_ms + debounce_ms. A null next_attempt_at still blocks the insert. A poll that observed a newer head while the job was running does not have to store it. If the post-agent pr view failed, head_sha is still the reviewed head, this function no-ops, and the next poll that learns the new head arms the job. Tests in src/store/poll/tests/schedule.rs drive both functions with explicit now_ms values and do not sleep. Include the same head passed twice, one case that starts from retry_count 1 and queued_head of head A and ends after head B with one job, retry_count 0, and a new deadline, one Absent::Open case on an already tracked target whose new head arms one delayed job, and one case that sets targets.head_sha to a new value the way set_known_head does after a succeeded run and expects one follow-up job without changing that run.
