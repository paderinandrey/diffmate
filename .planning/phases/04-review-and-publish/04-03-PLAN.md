    confirm_publication runs in one Immediate transaction. It inserts nothing when any finding on the draft is undecided, when a publication for the draft is submitted, or when any publication for the target is pending, sending, or unknown. On success it inserts publications.id as 32 lowercase hex characters from lower(hex(randomblob(16))), state pending, the event, confirmed_sha, and a snapshot JSON of the event, the kept and edited findings with id, decision, severity, path, line, side, title, and body, the limitation text only when limitation_included is 1, and the future improvements. It inserts one publish job in that same transaction with publication_id set, state queued, origin manual, and the process pid and start time. A failure rolls back both inserts. Return the new job id.

    execute_publish loads that job. It commits state sending on the publication before it calls create_review. commit_id is the run's head SHA, not confirmed_sha. The event on the wire is the snapshot event. On a CreatedReview, set the publication to submitted and store github_review_id, and set the job to succeeded. This task's fake returns a review id and records one call. The test seeds one anchored kept finding and calls confirm_publication then execute_publish. It expects one create_review, publication submitted, and the job succeeded. The inline comment body contains the finding title, the finding body, and the SPEC finding marker for that finding id. The review body contains the SPEC publication marker for the publication id. Do not write those marker characters into this plan file; copy them from SPEC.md Publication step 5. Commit subject: feat(publish): submit one review for a decided draft.
