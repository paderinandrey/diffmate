Binding project rules: no code comments; no unwrap, expect or panic! outside tests; every source file at or under 100 lines per commit; each task's commit passes the hk hook (whole suite, now including the crash tests); never --no-verify. D-14 makes DIFFMATE_CRASH_POINT the only new environment variable of the project, and it exists only in the feature build.

The macro keeps the release build free of crash code: `crash_point!("name")` expands to a statement carrying `#[cfg(feature = "crash-points")]`, so without the feature nothing is emitted; src/crash.rs defines the macro unconditionally (exported with `pub(crate) use`) and the async `reached` function only under the feature. Call sites `use crate::crash::crash_point;`. clippy already runs with --all-features, so the feature code is linted.

Tests time travel only one thing: in the budget test they set jobs.next_attempt_at to 0 between restarts with a direct SQLite UPDATE, standing in for the 1- and 5-minute retry delays that plan 02-05 already proves; nothing else in the database is written by tests. Process synchronization uses the crash-point stderr line, the fake agent's FIFOs and watch's event lines, read with blocking reads, never fixed sleeps.
