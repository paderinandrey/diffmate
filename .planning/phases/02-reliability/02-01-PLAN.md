The owner confirms the concrete shape at Task 1 before the migration touches a database.
Output: src/store/migrate.rs with the version 2 step, read-only handling of a version 1 file, a black-box upgrade test from a Phase 1 database and in-crate migration property tests.

Every later plan of this phase reads these columns. Proposed shape, added with ALTER TABLE ADD COLUMN: jobs.origin TEXT NOT NULL DEFAULT 'manual' CHECK in ('manual', 'automatic'); jobs.force INTEGER NOT NULL DEFAULT 0 CHECK in (0, 1); jobs.stop_reason TEXT CHECK in ('timeout', 'shutdown', 'user_cancel'), NULL when no stop was requested; jobs.retry_count INTEGER NOT NULL DEFAULT 0 CHECK at least 0; jobs.max_retries INTEGER CHECK at least 0, NULL until the job's first retryable failure fixes its budget from config.toml; jobs.next_attempt_at INTEGER (epoch milliseconds, NULL means runnable now); jobs.result_run_id INTEGER REFERENCES runs (id), the run a finished job's result is, including a reused run; targets.head_sha TEXT and targets.head_checked_at INTEGER, the last known PR head and when the runner read it; and index jobs_state ON jobs (state, next_attempt_at). The runs table is unchanged: failure_kind already allows 'timeout' and interrupted_cause already allows 'shutdown', 'user_cancel' and 'crash'. ## Trust Boundaries

| Boundary | Description |

| new binary → owner's existing diffmate.db | the upgrade writes to the owner's only copy of the Phase 1 state |
| concurrent diffmate processes → database file | two processes may open a version 1 file at the same time |

|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | src/store/migrate.rs on the owner's database | high | mitigate | Additive ALTER TABLE only, inside one IMMEDIATE transaction together with the user_version bump; phase_one_database_is_upgraded_and_kept compares every Phase 1 value before and after; optional VACUUM INTO backup chosen at Task 1 |
